Design recommendation

Make the marketplace explain the job before it shows the database.

SkillMake has a real point of view: audited, agent-installable skills for builders. The current site has taste, but the first screen spends too much attention on the ASCII logo and too little on why a user should trust, inspect, and install a skill today.

The improvements that matter

These are ordered by leverage. The first three change what users understand. The next two change what users do. The last two keep the system from drifting as the marketplace grows.

1. Hero

Lead with the workflow install job

Replace the ASCII-first hero with a direct promise: vetted skills that install repeatable workflows into Claude, Codex, and other agents. Keep ASCII as texture below the pitch, not the headline.

2. Paths

Separate filters from curated collections

Creators and engineers are filters. Tricks and Powerhouse are editorial paths. Put them in compact collection modules with one-line reasons to click.

3. Trust

Add evidence to every row

Rows should show video count, repo presence, reviewed status, install affordance, and curator pick. A row is not just a link, it is the decision surface.

4. Search

Make search teach the inventory

Add starter chips like "turn transcript into article", "review PR", "generate HTML", and "research last 72 hours". Users should learn the available jobs before typing.

5. Detail pages

Move install confidence above long prose

On skill pages, put install command, source, review status, video, and expected output near the top. Long explanation is useful, but it should not block trust formation.

6. Collections

Show the index before the documentary

Powerhouse currently starts deep. Add a compact five-skill index first, then expand into narrative sections and videos. Let users scan before asking them to scroll.

7. System

Tighten the UI rules

Keep green-on-dark, but define roles for blue, yellow, and red. Reduce radius drift to 8px. Use monospace for commands and identifiers, not every explanatory sentence.

8. Performance

Defer heavy media until intent

Collection pages should lazy-load videos and avoid speculative work until hover, scroll, or click intent. The product is a utility. It should feel instant.

Do not change

Do not turn this into SaaS wallpaper

No giant gradient hero, no stock illustrations, no generic feature blocks. The product wins because it feels like a useful registry built by someone who actually installs skills.

This keeps the current personality, but changes the first five seconds. The user sees what the product does, where to go, and why an install is safe enough to consider.

Design system rules

The aesthetic is already close. The win is discipline: fewer one-off radii, clearer color roles, and more intentional use of mono type.

typerule

Use Geist Sans for promises, descriptions, and explanatory copy. Use Geist Mono for skill names, commands, counts, source hosts, and short labels. This preserves the builder feel without making every paragraph harder to scan.

surfacerule

Use 8px radius for interface containers. Reserve pills for metadata. Keep rows flatter than cards. The site is a marketplace and registry, so density is a feature, not a compromise.
